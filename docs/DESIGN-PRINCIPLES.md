# GlassWeb design principles

GlassWeb is for people who want to understand a complex web system without first learning the choreography of DevTools. The interface should feel technically serious, visually surprising, and immediately legible.

## Answer first; complexity must be earned

The default experience is one human question, one short answer, four ordinary-language steps, and why the result matters. Technical layers, raw identities, certainty terminology, and the complete graph appear only after the person asks for proof. The five-layer X-ray is the payoff, not the entrance exam.

## Keep the real interface as the anchor

The captured page is not a thumbnail that disappears once analysis starts. It is layer zero. Every explanation begins at something a person can see or touch and expands outward from that fixed position.

## Show complexity with structure, not metaphor

Use aligned layers, stable geometry, restrained depth, labels, evidence states, and time. Do not translate software into cities, buildings, factories, pipes, planets, or arbitrary 3D worlds. Those metaphors look complex while making exact relationships harder to verify.

## Human meaning first; raw identity always available

`Loads the regional price` is easier to enter than `GET /api/pricing?region=••`. GlassWeb shows both. The plain-language label makes the graph readable; the raw identity keeps it accountable.

## Certainty must survive the visual treatment

Brightness means relevance, not truth. Motion means a recorded event, not decoration. An attractive trace must never erase the difference between observed, correlated, inferred, and unknown evidence.

## A trace is a story over evidence

The complete system can contain hundreds of objects. A person usually asks one question. Focus mode preserves the whole capture while illuminating only the entities and relations that answer that question.

## Unknown is a useful result

The browser cannot see private server execution, every framework handler, or every initiator. GlassWeb should render that boundary clearly. An honest gap is more valuable than a confident fictional edge.

## Motion carries time

Particles, pulses, and animation are permitted only when they represent a captured event or guide attention during a tour. Reduced-motion mode must preserve the same information without movement.

## Privacy is decided before storage

Redaction is not a cleanup pass over an indiscriminate recording. The recorder collects an allowlist and discards values, bodies, headers, cookies, storage contents, and query values before persistence. More powerful capture modes must be explicit, isolated, and optional.
